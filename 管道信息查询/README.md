# 管道信息查询（OpenPlant Modeler MSPython）

在 OPM 中**点取一个管道（或管道元件），立刻读出它的属性与定位信息**。只读插件：
不生成、不修改任何几何，也不写 ItemType。

## 能读到什么

点【点取管道】后在模型里点一个管道，面板分四组显示：

| 分组 | 内容 |
| --- | --- |
| 元素 | 元素 ID、EC Schema、EC 类（如 `PIPE` / `PIPE_ELBOW`）、实例 ID |
| 单位 | 属性长度单位，以及它是"自动标定 / 手动指定 / 兜底判断"哪一种 |
| 管道属性 | 管线号、公称直径、外径、壁厚、保温厚度、保温材料、管道等级、材质、元件名称、公称尺寸、长度…… |
| 几何 | **中心线标高**、**管底标高**（中心线标高 − 外径/2）、**保温层底标高**（再减保温厚度）、管段长度、起点 / 终点坐标、走向（水平 / 竖直 / 倾斜 + 坡度） |
| 推算 | **保温后外径**（外径 + 2×保温厚度）、保温层外半径、由外径反查公称直径 |

其中**几何完全由元素曲线算出**（单元格类管道没有曲线时改用元素范围兜底），不依赖任何属性；**管底标高 / 保温层底标高**由中心线标高配合外径、保温厚度算出。
属性则来自元素的 OpenPlant 3D 实例。

## 使用方法

1. 在 OPM 中打开三维 DGN 模型。
2. **Utilities → Python** 打开 Python Editor，加载并执行 `管道信息查询.py`。
3. 面板上点【点取管道】，然后把光标放在管道上点击；面板立即刷新。
   可**连续点取**多个管道，右键退出点取模式。
4. 【全部属性】把当前元素上的**全部 EC 属性原样列出**（含结构体 / 数组），
   用于排查属性名或确认项目实际存了哪些字段。
5. 【属性单位】用于手动指定属性数值的存储单位（见下）。

面板**始终显示在 OPM 之上**，不会被主窗遮住；OPM 整体最小化时它会随之收起，
切到别的程序时也不会浮在其它软件前面。实现方式是 ``AttachQtToolSetting``
把面板挂成 OPM 的工具设置窗（归主窗所有），另加一个**只在 OPM 处于前台时**
才把自己提到最前的定时器。

也可以直接用键入命令：

| 命令 | 作用 |
| --- | --- |
| `PYPIPEINFO PICK` | 打开面板（等同于执行脚本） |
| `PYPIPEINFO REPORT` | 先用鼠标选中一个管道，直接输出报告，不打开面板 |

## 实现要点（为什么这样做）

* **只读**：点取工具刻意**不实现** `_OnElementModify`（那是"元素即将被修改"的
  回调，只读查询走它会让框架进入修改 / 替换元素的流程）。改为用
  `_OnPostLocate` 记下元素 ID、`_OnDataButton` 读取后消费掉点击，
  因此点取不会触发任何元素修改动作。
* **不跨回调留 Bentley 对象**：元素句柄只在工具回调期间有效，出了回调再用会
  失效甚至让 OPM 崩溃。所以读取结果是一份**纯 Python 快照**，面板只记住
  元素 ID；切换"属性单位"是在快照上纯计算，要重新读元素时按 ID 重新取句柄
  （官方示例 `ECDumpUtility` 的做法）。
* **按需读属性：先枚举、再取值**（踩过的坑，最要紧的一条）：**绝不能拿一个
  可能不存在的属性名去问 Bentley**——`ECValue.GetValue()` 查一个该实例没有的
  属性会**让 OPM 直接崩掉**（不是返回错误码，catch 不到）。所以一律先用
  `ECValuesCollection` 枚举出实例上**实际存在**的属性名，只读其中存在的那些
  （`instance_property_names()`）——这正是官方示例 `ECDumpUtility` 的做法。
* **EC 实例绝不带出遍历**（踩了多次崩溃才定下的铁律）：`FindInstances` 返回的
  实例**只在这次遍历过程中有效**。一旦 `list()` 物化后留用、或把实例返回给
  别的函数稍后再访问，`GetClass()` / 枚举属性就会让 OPM **访问违例、进程直接
  消失**（catch 不到、日志都来不及写）。所以"查询 → 遍历 → 取值"全部写在
  `collect_instance_records()` 一个函数里，原地遍历 `collection[0]`，产出的是
  **纯 Python 记录**（属性名集合 + 属性值），出了函数再无任何 Bentley 对象。
  官方示例 `ECDumpUtility` 与本仓库 `支吊架公共库` 都是"在原地遍历 `[0]`"。
* **EC 读取不在工具回调里做**：实测在 `_OnDataButton` 回调内部访问 EC 实例会让
  OPM 崩溃，而同样的调用在普通脚本上下文里完全正常（诊断脚本就是脚本上下文，
  跑得通）。因此点取工具只把**元素 ID 放进队列**，真正的读取由面板事件循环在
  `PythonMainLoop()` 返回之后执行——与"直接执行脚本"处在同一上下文。
* **实例资格只由 schema 决定**：管道数据都在 `OpenPlant*` schema 里；本仓库
  支吊架插件写的 ItemType 实例库名是 `PipeSupportComponents`、类名也以 `Pipe`
  开头，光看类名会把支吊架的设计长度当成管径，因此非 `OpenPlant*` 一律不认。
* **分阶段日志**：每次读取都会把进度逐行写进调试日志。万一某一步让 OPM 崩溃，
  **日志最后一行就是出问题的步骤**（几何 / EC 实例查询 / 枚举挑实例 / 文本属性 /
  长度属性），并且会逐个候选实例记录 `Schema.Class + 属性个数 + 得分`。
* **MSPy 符号按名字补齐**（踩过的坑）：`from MSPyX import *` 并不导出全部符号，
  `ISessionMgr` 就是典型漏网的，而且"某个符号由哪个 MSPy 模块导出"各版本还不
  一致。所以两个模块都先把通配导入拿不到的符号，在**已加载的 MSPy 模块**里按
  名字查找补绑（`fill_mspy_symbols`），不再逐个猜模块；导入时还会自检，
  缺符号就直接显示在面板上，而不是等点取时才报一个莫名的 `NameError`。

## 关于"属性单位"（重要）

OpenPlant_3D 的 EC Schema 里，长度类属性（`OUTSIDE_DIAMETER`、
`INSULATION_THICKNESS` …）是**裸 double，没有单位标注**，不同项目的 DGN 可能
存米、也可能存毫米。本插件不硬编码，处理方式分三层：

1. **自动标定（首选）**：拿属性的 `LENGTH` 与**同一段管的几何长度**互校——
   两者描述的是同一个物理长度，比值必然是 1（毫米）或 1000（米）。标定成功后
   面板会说明"属性单位按……标定为米（误差 x%）"。
   **单元格（Cell）类管道没有中心线曲线**时，改用元素范围（包围盒）的**最长边**
   当基准——对直管段它就等于管段长度（实测某 DN150 管：包围盒 X 跨度 2771.6 mm
   ＝ 属性 `LENGTH` 2771.57 mm，标定结果"毫米"，误差 0.001%）。
2. **兜底规则**：标定不成立时按"数值 < 1 视为米，否则视为毫米"判断，
   并明确提示**建议手动确认**。
3. **手动指定**：面板【属性单位】下拉可直接选"毫米 / 米"，立即重算。

报告里每个长度属性都会带上**原始值**（备注列显示"原值 0.1683"），
配合"由外径反查公称直径"的交叉校核，读到的数是否合理可以当场判断：

* 外径能反查到标准管径、且与属性公称直径一致 → 读数可信；
* 外径反查不到、或与公称直径差很多 → 面板会提示核对单位。

## 读的 EC 属性

实例取自元素上挂的 OpenPlant 实例（基类 `PIPING_COMPONENT`，
类如 `PIPE` / `PIPE_ELBOW` / `PIPE_TEE` …，Schema `OpenPlant_3D.01.08`）：

* 文本：`LINENUMBER`、`NAME`、`COMPONENT_NAME`、`NOMINAL_SIZE`、
  `SPECIFICATION`、`MATERIAL`、`MATERIAL_MARK`、`GRADE`、`INSULATION`、
  `PIPE_FLANGE_TYPE`、`SHOP_FIELD`、`SPOOL_ID`
* 长度：`NOMINAL_DIAMETER`（缺失时退回 `NOMINAL_DIAMETER_RUN_END`）、
  `OUTSIDE_DIAMETER`、`WALL_THICKNESS`、`INSULATION_THICKNESS`、`LENGTH`、
  `ELEVATION`

元素上可能同时挂着别的 EC 实例（例如本仓库支吊架插件写的 ItemType 实例
`PipeSupportComponents`）。挑选时会**优先 OpenPlant 系 Schema 的实例**，
ItemType 实例一律不参与，避免把支吊架的设计长度当成管径。

## 已知边界

* 只有 **MicroStation 普通图元**（没有 OpenPlant EC 实例）时，面板只给几何信息
  并明确提示——这时"中心线标高、走向"仍然可用。
* 轴线几何取自元素曲线；直线 / 折线长度精确，含圆弧时长度按曲线长度取，
  取不到则退化为折线近似（备注列会注明"折线近似"）。
* **管道是单元格（Cell）时没有中心线曲线**（OPM 里很常见）——此时改用元素范围
  （`RangeLow` / `RangeHigh`）兜底，报告给出**包围盒中心**（≈中心线位置，含
  近似中心线标高）、包围盒尺寸与范围来源，并明确标注"包围盒近似"。包围盒截面
  与「外径 + 2×保温厚度」吻合时，还会给一句正向确认（只在吻合时说话，不吻合
  不报警——弯头 / 阀门的包围盒本来就不是圆截面）。
* 数值属性读到 `nan` / `inf`（对字符串属性调 `GetDouble()` 就是返回 `nan`）
  一律当作"没有值"，不会出现 "nan mm" 这类显示。
* 若所选元素的曲线是**闭合轮廓**（不是中心线），起终点与中心线标高按轮廓首点
  计算，面板会明确提示**不能当作管道中心线使用**。
* 公称直径反查用的是常用钢管外径系列（DN15~DN1200），非标准外径会提示核对。

## 单测

不需要 OPM，普通 Python 即可：

```bash
python 模块/tests/test_pipe_info.py
```

覆盖单位标定 / 兜底 / 长度换算、外径反查公称直径、走向判定、报告排版，
并用**假 EC 实例**验证属性读取与实例挑选逻辑（数值属性不会被当文本读、
ItemType 实例不会被误当成管道）。
