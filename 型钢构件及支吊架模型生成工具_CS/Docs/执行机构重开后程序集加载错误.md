# 执行机构重开后点击报 SteelSectionProbe 找不到

用户后续明确要求已放置件脱离插件仍可操作；本文自动加载配置只用于恢复现有依赖插件的版本，最终交付方向与验收见[无插件交付要求](执行机构无插件交付要求.md)。

2026-10-31。对应用户截图的 `System.IO.FileNotFoundException`，文件名为 `SteelSectionProbe`，调用栈为 `Assembly.Load → BMECObject.GetComponentClassFromInstance → createComponentInstance → Init`。

## 原因与证据

实际工作集 `SSP_CEL_VALVE_ACTUATOR` 的 CREATION_ATTRIBUTE 指定 `ASSEMBLY_NAME=SteelSectionProbe`、`NAMESPACE=SteelSectionProbe`、`CLASS_NAME=CelValveActuatorComponent`。本机 SDK 的 GetComponentClassFromInstance 在 IL 0227–0229 按该名称调用 Assembly.Load；异常发生在创建处理器及调用 CEL 几何回调之前。

本机标准主插件 DLL 存在，并通过 PE 元数据读取确认包含公开的 CelValveActuatorComponent。当前项目没有提供主插件自动加载配置，磁盘 Configuration 下也未检索到 SteelSectionProbe 的加载配置。先前的首次安装步骤只让用户当次手动 mdl load，遗漏了重开时组件处理器的部署要求。这个缺口与“当次能放置、重开点击时报程序集找不到”一致。活动用户配置和会话实际加载状态尚未在 OPM 内核验，若显式加载仍失败，需要继续定位其具体依赖或实际路径。

这次异常不能证明 CEL 二进制损坏、数据丢失或关联错误，也不证明重开持久化已经通过。不能通过改变 CEL 原点、重新放置或修改操作柄来解决程序集查找失败。

## 先手动验证

1. 关闭发生致命错误的 OPM，重新启动，使用测试 DGN 副本。
2. 点击执行机构之前，在键入窗口执行下面命令。先确认加载成功；如果命令本身报错，停止点选并保留完整报错。

   ```text
   mdl load "E:\Code\Bentley_Python_plugin\型钢构件及支吊架模型生成工具_CS\bin\Release\net48\SteelSectionProbe.dll"
   ```

3. 加载成功后点击原来的执行机构。预期不再出现本次 SteelSectionProbe 文件找不到的错误；随后只选执行机构运行 `STEELPROBE ACTUATORCHECK`，核对处理器、CEL 数据哈希和阀门关系。无需新放一件。

如果实际插件放在别处，命令应使用那一份包含 CelValveActuatorComponent 的 DLL。不要同时加载不同目录的同名版本。

## 持久配置

已准备 `Deployment/SteelSectionProbe-Autoload.cfg`，内容为：

```text
MS_ADDINPATH > E:/Code/Bentley_Python_plugin/型钢构件及支吊架模型生成工具_CS/bin/Release/net48/
MS_DGNAPPS > SteelSectionProbe
```

第一行让宿主搜索到主插件，第二行在打开 DGN 时自动加载。`>` 追加条目，保留其他原生应用。主插件 Run 当前只返回成功，不会自动打开功能页、开始放置或改写模型。

手动加载验证通过后，正常退出 OPM，把该 cfg 复制到：

```text
C:\ProgramData\Bentley\OpenPlant 2024\Configuration\Organization\SteelSectionProbe-Autoload.cfg
```

如果使用其他安装目录，先修改 cfg 第一行；若已存在同名 cfg，先核对并备份。该文件应与此说明一起使用，不需要改 Schema 或替换 DLL。本机 `config/msconfig.cfg` 在 Organization 层包含 `$(_USTN_ORGANIZATION)*.cfg`，故放在 Organization 根目录，不是 Cell 子目录。本次只在仓库准备文件，未写入 ProgramData。

重开 OPM，核对“配置变量”中的 MS_ADDINPATH 含上述目录、MS_DGNAPPS 含 SteelSectionProbe，并在 MDL 应用程序中确认主插件已加载，再点旧件。预期无需再次手动 mdl load，即可选择、校核已有件。再退出并重开复核一次。配置存在但未加载时先检查配置是否生效、路径及启动时的加载报错，避免重复触发致命异常。

移走该 cfg 可撤销此次自动加载配置，但包含这些自定义参数化组件的 DGN 仍需要对应插件才能正常编辑。把 DGN 发给别人时也要提供匹配插件、Schema 与加载配置。旧 V3～V5 类使用另一程序集 ValveActuatorCallbackCheck，本文件仅处理截图点名的主插件加载问题。

## 验证边界与资料

本轮完成 SDK/Schema/部署配置只读核对、DLL 公开类型元数据核对及配置文件静态核对；未启动或控制 OPM，未修改 DGN、CEL、已安装 Schema 或 DLL。上述效果是待用户执行的预期。

Bentley 官方说明：[配置变量](https://bentleysystems.service-now.com/community?id=kb_article&sysparm_article=KB0108868) 定义 MS_ADDINPATH 为托管 AddIn 搜索目录，MS_DGNAPPS 为打开 DGN 时自动加载的应用列表。
