# 支吊架组合绑定

本模块管理管夹/耳轴的组合引注及承重钢构的ISO材料归属。原生管夹仍是出图定位点，承重钢构保存为显式引用；不将钢构实体转换为管道组件，不建立随管移动关系。材料通过独立的原生附加材料对象提取。

## 使用

1. 在首页“支吊架”分类打开“支吊架组合绑定”。
2. 点取本插件正式创建的原生管夹、立管耳轴或弯头耳轴；读取现有原始编号及绑定列表。
3. 点击“点取承重支架”，连续选取已确认的钢构整组；右键或“结束点取”退出。
4. 上移、下移或移除，检查预览；点击“保存绑定”。
5. 重新提取ISO，预期同一个管夹图符的引注显示：

```text
(1)A1-DN100-C1
(2)G4-A-500-250
```

首行固定为管夹原编号，附加行按列表顺序编号。解除全部后再次保存可恢复原单行引注。“重新读取 / 放弃修改”丢弃草稿；“核对 / 更新编号”重新读取承重构件的当前编号，随后须保存。删除的构件需移除或重新点取。同编号的不同元素可以分别关联；重复选取同一元素会被拒绝。

用户已在宿主确认第一版多行引注功能良好，圈码显示问号。当前统一使用ASCII括号序号；旧绑定读取后点击保存即可升级，不必重新点选钢构。旧绑定也可通过“同步本模型组合材料”补齐材料；该按钮只同步已保存绑定，不改尚未保存的草稿或引注序号。

只接受活动三维模型，最多19个承重支架。目标须具有本插件正式原生身份记录、有效原生图形、SSPPC/SSPTR标记及一致的材料编号；复制出旧身份记录、只读或锁定目标、参考对象、未确认预览、块内子件及没有清单的普通实体均不接受。承重类别按既有材料Assembly角色白名单识别，包括T架、门架、N1～N4、悬臂/三角/L架、G2/N8、Q1/Q2。

## 持久化与出图

新增独立ItemType库`SteelSectionProbeSupportBindings`，类型`SupportBinding`，固定String字段`Payload`、`BaseTag`、`CombinedTag`。Payload为版本1 JSON，记录目标`SupportInstanceId`、`BaseTag`和有序`Members`；每项含持久模型ID字符串`ModelId`、`ElementId`、材料`ItemType`、`Tag`与`SupportType`。不保存会话指针到DGN。类型名不含实例尺寸或编号。

列表完整存储，页面用正常换行。ISO引注用`$ `分行（美元符号后加空格），避免 `$(2)` 被当成属性。材料描述写回支架 DESCRIPTION，格式为 `(1)编号 (2)编号`，解除绑定后恢复原描述。原生NAME、管夹的PlacedPipeSupport记录、配方、三维/ISO位置及PipeSupportComponents各单件编号保持。更新ALIAS与新增附加项在同一次独立事务中完成；临时`DeferCommits=false`，finally恢复原值，不提交全局待处理集合。API所有的文档对象不释放，禁止用游离BMECObject写回；成功须重读确认原始记录不变、ALIAS及Payload完全一致，失败回滚并刷新缓存；回滚或恢复失败明确报错。

## ISO材料及共架

一套门型架或T型架可以绑定多个管夹，包括不同管线。用户指定按关联管道中最大的公称直径DN计一套材料，其余图只显示引用编号。同DN并列时保留已有计材归属；首次按持久原生实例ID确定一根。按模型ID/元素ID识别真实钢构，不按相同编号去重；同型号两套架仍有两条真实材料对象，ISO可按其正常规则汇总数量2。

工作集自带`ADDITIONAL_MATERIAL`在Isoextractor已映射`CT_ADDITEM`，`IE_DESCRIPT=this.TEXT`，`PIPING_COMPONENT_HAS_NOTE`已纳入提取。新服务沿用本机SDK `SDKExamples/NoteExample/Keyins.cs`和只读元数据确认的顺序：创建附加材料、以UOR接口写位置/毫米接口写管径、继承父管网络/管段/管线号，Create→AddNoteToComponent→Serialize。该通道也见[Bentley附加材料说明](https://bentleysystems.service-now.com/community?id=kb_article_view&sysparm_article=KB0033476)。当前本工作集无需改Schema或全局报告样式，其他工作集必须有对应默认映射。

材料描述为钢构编号，常见`×/∠/°`转ASCII`x/L/deg`，剩余非ASCII码点用可见的ASCII转义保存。每套钢构仅一个附加材料对象，位置在计材管夹站位，关联其真实父管（直管或弯头），因此只随该父管提取。使用宿主附加材料的标准定位标记，不重建第二套钢构。材料属于整套G4/门架编号，不在ISO展开复制立柱、锚板、锚栓等本地明细；原PipeSupportComponents统计始终按原钢构一份。

附加材料根另存`SteelSectionProbeSupportBindings/BomMaterial`，Payload版本1记录`ModelId/CarrierElementId/ItemType/Tag/OwnerSupportInstanceId/ParentInstanceId/OwnerDn/NoteInstanceId`。只有记录和实际图形身份匹配的本插件材料才可修改/删除，其他用户NOTE不动。保存时扫描活动模型对受影响钢构的所有已保存绑定，用实际父管DN选择归属；新增更大管夹时删除原材料、创建新归属，解除最大引用则转给次大，最后引用解除则删除。与ALIAS/绑定在同一个事务中完成；失败同时回退绑定和材料，新对象缓存回收，原对象缓存刷新，恢复失败明确保留所有权。

“同步本模型组合材料”在独立事务中重新核对全部已保存绑定、补齐旧绑定材料及清理无引用的孤立材料，可在删除管夹/钢构后或出图前使用；不依赖自动事件监听。被删钢构的悬空引用仍可逐个移除，不相互阻塞。活动模型之外的引用不受支持。源管径与管夹计划不一致时拒绝计材，需先更新管夹。

当前管夹类和自带耳轴类必须已按原部署脚本安装ALIAS引注映射；只更新DLL不能替代这些已有前置映射。新材料行的提取/分类、同架单次计量、Undo/Redo和重开仍需宿主验证；第一版多行引注成功不代表此次新增材料功能已通过实测。

## 验证

离线入口：

```powershell
dotnet run --project Development/SupportBindingCheck/SupportBindingCheck.csproj -c Release
dotnet run --project Development/HomeCheck/HomeCheck.csproj -c Release
dotnet run --project Development/PipeClampIsoCheck/PipeClampIsoCheck.csproj -c Release
dotnet run --project Development/HomeUiCheck/HomeUiCheck.csproj -c Release -- <工程绝对路径>
```

SupportBindingCheck链接真实领域、Reader、Store、Editor、LocateTool及页面，API替身检查六种现有原生类、立即/延迟提交开关、排序/解除、读回、同编号不同元素、失败回滚/回滚失败、过期目标/改号/删除/只读/锁定/模型切换/许可/Undo、无效JSON、上限、排队回调取消、捕捉恢复和页面状态。真实XAML覆盖400×560/600/880/1080、520×720、四档DPI、固定操作区，生成预览截图。替身不执行Bentley原生Serialize、对象缓存、ItemType持久层或ISO引擎。

新增材料回归覆盖DN100/150/300多管夹和多管线共架、同DN并列、不同钢构同编号、较大管转移/解除回退/末引用删除、重复保存幂等、3档UOR×3档Schema坐标单位、材料Create/关系/Serialize/附加项/读回/删除失败、全模型同步/孤立清理及旧Version1升级。API替身不执行真实Bentley内核、Persistence或ISO引擎。

宿主验收：

1. 新放A1和G4后绑定，另放门型架添加第三行；保存后在构件特性中核对ALIAS与新增附加项，单件材料编号仍分别保留。
2. 一套G4分别绑定DN100和DN300两根管道，两个引注都有G4编号，仅DN300的ISO材料表出现G4一套。再加DN150及另一根DN300，确认不重复计材。同编号的第二套G4应另计一套。
3. 新放F6/F7/F10和F2/F2-HE/F4/F5，分别绑定，核对各自原生图符及多行引注；不能将A1结果泛化为所有耳轴均通过。
4. 保存失败无残留；撤销/重做、关闭DGN重开、操作柄编辑或父管移动后，检查绑定附加项与ALIAS仍保留，源钢构位置保持原业务行为。
5. 改钢构编号后核对/保存，删除钢构后核对提示；切换模型、锁定/只读管夹、重复开始点取、取消/离开时阻止过期写入。
6. 重新提取ISO，检查ASCII序号、多行框、附加材料数量与行分类；解除DN300计材引用后重新同步，应转到其余最大DN，解除全部材料应消失。删管夹或删钢构后同步，孤立材料应清除。此次新材料通道尚未取得宿主验收证据。
