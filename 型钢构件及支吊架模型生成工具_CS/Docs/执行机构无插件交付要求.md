## 当前依赖的原因

V6/V6.1 已将所选 CEL 文件快照放进实例 SSP_CEL_DATA，但组件是 SSP_CEL_VALVE_ACTUATOR，参数化创建属性指向 SteelSectionProbe.CelValveActuatorComponent。存储几何数据没有同时消除处理器依赖。OPM 重读并创建参数化处理器时按名 Assembly.Load，缺 DLL 就出现用户截图中的错误。

## 推荐验证的路线

插件仅负责选择、导入和安装；落盘结果由 OPM 原生非参数化几何机制管理。优先研究保留原生 GEARBOX_OPERATOR 类、保存实际 CEL 图形、安装变换和 VALVE_HAS_VALVE_OPERATING_DEVICE 关系，避免持久件要求加载自定义几何处理器。不是把原生类的全局处理器改成本插件，也不是仅把自定义处理器名改回 stock 后继续参数化重生成。

这条路线是候选，尚未证明已放件能在没有插件的进程中正常完成全部官方交互。尤其需要确认原生三个调节柄、父阀门随动、重生成不会重画成默认齿轮箱，以及旧实例迁移后的关系身份。已经存成自定义参数化类的实例需要受控迁移，单纯更新新放置代码不会改变旧件的依赖。

另一条可提供普通图形交付副本的路线是固化为普通 CEL/原生图形：普通选择、整体移动旋转由 CAD 图形工具处理；这不能被当作阀门关联、官方三个调节柄或自动随动已保留的证明，不可默默用它替代用户原有的阀门交互要求。

## 本机 SDK 新核对结果

只读 PE/IL 核对本机 24.00.03.53 Bentley.OpenPlant.Modeler.Api.dll：

- VALVE_OPERATING_DEVICE 有 UPDATE_GRAPHICS/boolean；手动执行机构基类有 Geometry/binary。
- BMECObject.PerformInit 与 CreateByElementHandle 读取 UPDATE_GRAPHICS；值明确为 false 时传 true 给 Init 的布尔参数。
- Init 在 IL 02D4 检查该参数；true 跳过 createComponentInstance，后段把 UPDATE_GRAPHICS 设为 false。
- CreateByElementHandle 在没有参数化 component 时，从实际持久图元构造原生 EditElementHandle，逆安装变换后交给 SetNonParametricElement。
- get_IsParametric 只是检查 _component 是否非空；SetNonParametricElement 不是自动清掉已创建参数化处理器的模式转换器。
- 原生 GearBoxOperatorScript.Create3DElements 直接使用尺寸创建默认齿轮箱，不从 SSP_CEL_DATA 读 CEL。因此不能仅改回原生处理器并假定形状保留。

这些证据表明原生持久几何模式值得验证，不是“宿主所有自定义件必定要求我们的 DLL”。但仅设置 UPDATE_GRAPHICS=false 或让一次显式包装器 IsParametric=false，都不证明默认重读、缓存、官方编辑和重开一致。不要直接在生产模型中批量改这个布尔值。

历史 V1 失败只证明对现成参数化手轮调用 SetNonParametricElement 没有切换模式；它在 Serialize 前退出回滚。V2 显式非参数化候选尚未完成宿主验收，随后按用户要求转向管夹同款自定义回调。不能把 V1 结果扩大为原生固化路线已全部否定。

Bentley 有[从 CEL 创建自定义组件的官方入口](https://bentleysystems.service-now.com/community?id=kb_article&sysparm_article=KB0101595)，但该文章针对旧版本阀门示例，不能作为 OPM 2024 执行机构关联及三个调节柄已受支持的依据。

## 必须由用户验证的交付标准

在独立测试 DGN 副本执行，原生产文件、原 CEL、原 Schema 和旧 DLL 均保留备份。开发阶段离线核对或原进程里的缓存命中不算通过。

1. 一次受控固化后核对 CEL 外形、用户约定安装原点、阀门关联、变换及实际保存模式。
2. 正常保存、完全退出 OPM，测试进程不加载主插件，也不加载旧 Callback 验证 DLL。临时禁用自动加载配置，并让测试环境找不到对应插件，排除“没有打开 UI 但 DLL 已加载”的假通过。
3. 重开，选择执行机构不弹插件加载错误；用原生工具移动/旋转并保存，再退出重开。
4. 分别验证官方三个调节柄、父阀门移动/旋转后的随动、重生成、Undo/Redo和双向关联；外形不恢复成默认齿轮箱。
5. 再在找不到外部原 CEL 的环境重开，确认实际图形仍可恢复。未通过任一必要交互就保留候选状态，不替换当前主线。

本轮仅调查并记录要求，没有更改放置实现、实例模式、Schema、DGN、已安装 DLL 或自动加载设置。
