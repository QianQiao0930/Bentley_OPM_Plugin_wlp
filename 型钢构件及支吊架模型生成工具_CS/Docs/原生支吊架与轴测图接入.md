# 放置管夹：原生支吊架与轴测图接入

2026-10-15当前正式版已经升级为SSP_PIPE_CLAMP参数化组件，继承SUPPORT_LOCATION并保存完整建模配方，以原生Support处理器接入移动/旋转与随动。A1修复版经用户实测正常，创建和后续回调日志均无异常；正式接入规范、安装及验收以[正式管夹原生编辑与随动](正式管夹原生编辑与随动.md)为准。本篇下方SUPPORT_LOCATION非参数化流程及“不增加事件监听”的说明保留作旧版记录；当前仍不增加补偿移动监听，但由参数化组件参与OPM原生编辑。

## 当前用法

2026-10-15仅调整A1/A2编号源为A1-DN{管径}-{材料代码}、A2-DN{管径}-{材料代码}。页面新增材料代码输入与独立记忆，默认C1，去首尾空白并转大写，仅英文字母数字；不锈钢按材料段S填写，不另追加S后缀。A1角度/螺杆尺寸继续用于几何和详细规格；编号输入不自动改变材质或创建隔离层。原材料记录及ALIAS同步，已有工作集映射直接适用。旧模型不批量转换，需新放置并重新提取ISO。

重启OPM加载本次DLL，在首页进入“放置管夹”，按原流程点取管道、调整方向/沿轴位置、更新预览、确定生成。选中**活动三维模型中的可写原生PIPE直管**时，九类构件确认后都会成为有父管关系的原生支吊架，可用项目原有ISO提取流程出图，无需执行A1TEST命令。预览阶段不附加业务关系或材料记录。

| A1 | U-BOLT CLAMP | A1ClampPlan.AssemblyTag，例如A1-DN100-C1 |

2026-10-14按用户反馈调整：引注**完整使用现有管架编号**，不另拼DN/型钢等规格，不追加原生流水号，也不擅自删除原编号本来就有的尾段。E1为 `E1-B-107`，不再输出 `E1-DN100-B-L50x50x6-H107-0001`。A1/A2现按2026-10-15的新业务编号生成，不在ISO层另造编号。原编号中的度数符号等字符保持；单件编号为空或含控制字符/ISO换行符$时拒绝确认。详细的ASCII规格与英文名称仍用于BOM描述，原插件中文材料九字段契约保持。

九类统一使用原生 `SUPPORT_LOCATION`（支架位置）类，继承SUPPORT的ISO提取规则，经 `ClassMap(...,"SUPP")` 使用工作集的通用简图。用户截图已确认正式模块的双横线与引注显示。当前Support Tag Labels读取IE_TAG；默认IE_TAG=this.NAME，而SUPPORT.NAME由DEVICE_TYPE_CODE和NUMBER计算，不能把显示编号直接当唯一实例编号，否则自动编号会污染引注，同型号重复放置也有冲突风险。

新版分别保存：`DEVICE_TYPE_CODE=SSPPC`为本工具管夹标记，`NAME`由原生命名管理，`ALIAS`原样保存AssemblyTag；JSON的IsoTag为显示编号，新增可选NativeName保存实际实例编号，Version仍为1。事务内及持久对象重读后均检查ALIAS和标记，丢失则回滚。A1TEST试验类不走此标记。

### 首次部署引注映射

本次需要给目标工作集的Isoextractor补充Schema安装一条限定映射。运行 [Install-PipeClampIsoTag.ps1](../Deployment/Install-PipeClampIsoTag.ps1)，`-SchemaPath`指向该工作集 `Standards/OpenPlant/Schemas/OpenPlant_3D_Supplemental_Isometrics_Isoextractor.01.08.ecschema.xml`；不传Apply时仅预览。确认目标后：

```powershell
.\Deployment\Install-PipeClampIsoTag.ps1 -SchemaPath '<目标工作集Schema完整路径>' -BackupDirectory '<备份目录>' -Apply
```

脚本从当前PLANT_BASE_OBJECT复制默认BOM_LABELS到SUPPORT_LOCATION，仅修改IE_TAG：

```text
IIf(IM.Match(this.DEVICE_TYPE_CODE,"SSPPC"),IM.GetValue("ALIAS",(this.NAME)),(this.NAME))
```

其他SUPPORT_LOCATION仍回落到原表达式；其他类别、符号库、style.xml、材料描述及既有件状态映射保持。若基类IE_TAG已有项目表达式，则保留该表达式作为回落。目标类已有其他项目BOM标签时明确拒绝覆盖；重复安装幂等。每次实际写入先做字节级备份及SHA256收据，临时文件验证后替换；可用收据Backup路径恢复原文件。将来项目默认BOM映射变化时，需要复核这个类级副本，不要直接覆盖项目自定义配置。

本机目标为CINF_International_Projects_Workspace/CINF_F1263AA，本次已安装并备份；结构比较确认原240个Schema节点保持，只新增上述类级映射且仅IE_TAG与基类不同。更换工作集或只复制DLL到另一台电脑时，也要安装对应映射。安装后**重启OPM、新放置管夹并重新提取ISO**；旧件没有SSPPC/ALIAS，不自动迁移，旧出图DGN也不改。当前离线验证不证明真实ISO引擎已经执行此新表达式，须检查新L00的IE_TAG=E1-B-107及图中方框。

### 组合支架多行引注（2026-10-15新增组合绑定模块）

当前实现以现有原生管夹或耳轴为出图根，新增独立附加项保存承重钢构有序引用，不额外创建出图根或复制材料。首页“支吊架组合绑定”支持点取、排序、移除、解除全部及主动核对更新编号，保存后ALIAS输出组合引注。详细契约与验证见[支吊架组合绑定](支吊架组合绑定.md)。此次只关联普通承重钢构，不组合多个已有原生管夹；未来若组合多个出图对象，仍须明确排除重复符号和材料，不能凭同坐标自动合组。

显示目标例如：

```text
(1)A1-DN100-C1
(2)G4-A-500-250
```

轴测 NOTE 模板是 `$(IE_TAG)`。`$(2)` 和 `$$(2)` 都会把 `(2)` 当成属性删掉，所以第二行编号会消失。换行写成 `$` 加一个空格：`(1)A1-DN100-C1$ (2)G4-C-500-500`。材料表不换行，用空格写成 `(1)A1-DN100-C1 (2)G4-C-500-500`，并写回支架 `DESCRIPTION`；解除绑定后恢复原来的材料描述。普通 C# 换行只用于页面预览。原始列表与顺序由独立附加项持久化，再由组合服务编码，不能把$串写回各子件AssemblyTag。单件入口继续拒绝$，组合绑定入口单独负责编码。Bentley官方[阀门多行引注示例](https://bentleysystems.service-now.com/community?id=kb_article_view&sysparm_article=KB0101124)演示以$拼接属性及NOTE框；[CONNECT多行标签示例](https://bentleysystems.service-now.com/community?id=kb_article_view&sysparm_article=KB0098533)同样采用此分隔符。

用户截图已确认第一版多行框生效，但圈码显示问号，现统一改ASCII(1)/(2)/(3)。材料新增走工作集已有ADDITIONAL_MATERIAL/CT_ADDITEM通道，每真实承重钢构只在最大DN父管计一套，其余只引用；同DN保留原归属。原管夹及钢构本地清单保持，材料同步和孤立清理详见组合绑定说明。新增材料提取/分类、数量、Undo/重开仍须宿主验证。

辅助线和参考来源保持普通Cell与本地材料清单，页面明确提示不建立ISO关联；参考管轴物化的临时线不能冒充活动管道。已经生成的普通Cell/旧试验件不批量转换，需新放置。真实管道身份不明、被删/锁定、模型或单位变化、预览后管轴/管径/外径/保温变化、定位超出管轴段时拒绝确认，避免关联到错误对象。

本轮提供原生父管关系和ISO数据，不增加自动跟随监听。移动后支吊架是否跟随、ISO支撑点是否同步、保存重开和Undo/Redo，仍须单独实测；不能仅凭关联存在认定这些行为都已实现。

日志：`%LOCALAPPDATA%\SteelSectionProbe\logs\NativePipeSupport\latest.log`，每次原生确认覆盖，含实际DLL/MVID、类别/规格、父管、目标点、原生元素、编号及异常。A1TEST仍保留自己的日志入口。

## A1试验已经确认的事实

用户在2026-10-14的实测图片与实际L00/SHP报告已确认：A1可保留自定义三维外形，建立DEVICE_HAS_SUPPORT关系，正确定位ISO符号，生成编号和材料表。试验过程暴露的三个问题必须作为后续接入约束保留：

1. `BMECApi.DeferCommits=true` 时Create/Serialize可以返回成功但只排队，ID仍是 `mechanical`。本次新建范围临时设false，finally恢复；不得提交或清空全局DeferedChangeSet。
2. 自定义非参数化几何的 `GetSectionalDataForSupport` 未自动计算SUPPORT_POINT。三维变换正确不代表ISO位置正确，必须调用 `SetDoubleValueFromMM` 写目标轴点XYZ，序列化后按Schema单位读回；不将UOR直接写入EC字段。
3. STATE空值在当前项目映射成IE_EXISTING=1，表现为虚线、无材料表。新构件显式Design/SHOP，保存后校验；不要为修一个构件改全局“既有件”提取规则。

A1的成功不能替代新SUPPORT_LOCATION类、全部九种实体和正式页面暂态预览在OPM中的验证。

## 共用接入接口

- `OpenPlant/NativePipeSupport/NativeSupportGraphics.cs`：固定原生EditElementHandle，SetNonParametricElement、Create、设置变换、Serialize；句柄及离线图形存活到全部回调序列化结束。SetNonParametricElement会提取离线图形描述，不能拿正式模型元素直接传入。
- `NativeSupportData`：Design/SHOP、按mm写/读SUPPORT_POINT；反查唯一DEVICE_HAS_SUPPORT、三维和ISO各1mm容差、非参数化外形。只校验数据，不暗中移动对象。
- `NativePipeSupportWriter.Create`：授权/Undo保护，独立宿主事务、立即提交、缓存所有权、附加材料/记录、持久对象重读验证，最后释放暂态预览。失败回滚；回滚失败明确报错并保留缓存或包装对象所有权。
- `NativePipeSupportSource`：用点取时的原生实例ID、元素ID、模型指针标识、单位、轴段和管径快照重新确认父管；构建沿轴的正交坐标架及逆变换。正式几何用当前真实计划重建，先逆变换为局部，再由原生变换放回，防止重复平移/旋转，支持各类别原有的水平/斜管/立管范围。
- `NativePipeSupportDefinition`：九类原AssemblyTag引注、独立ASCII材料描述及原生类/标记选择。`SUPPORT_LOCATION.NOMINAL_DIAMETER` 在本机Modeling补充Schema为string，必须检查实际字段类型，不能照抄UBOLT_GUIDE的double写法。
- `NativePipeSupportStore`：根元素的 `SteelSectionProbeNativeSupports/PlacedPipeSupport` 单独JSON Payload，Version=1，保存类别、DN、原生类、父管/支架实例ID、实际ISO编号、描述及点坐标。原PipeSupportComponents记录由原Attach方法写在同一根元素上。

`PipeClampPreviewSession`集中处理九类确认，不在每个Builder重复EC写入。A1TEST调用相同Writer/Data/Elements/Graphics核心，继续保留更严格的试验选型和检查。扩展其他模块时复用这个边界，提供真实父管、离线局部几何、目标轴点和原材料回调；不要绕开源复核、事务与单位检查。

## 预览、失败和撤销

正式页面预览通过COM暂态容器显示图形副本。为使用现有可靠的GetElementByID64桥接，在同一短事务内物化普通Cell、创建暂态副本、立即删除该临时Cell；这对Add/Delete不能跨事务拆开，也不能在中间写材料数据。预览更新先建新显示，再释放旧显示；Reset失败仍保存所有权，取消/关闭可重试回收。

原生确认事务中只创建最终原生根元素；预览释放只涉及暂态容器，Undo不会恢复出没有会话管理的普通预览块。辅助线/参考来源确认时才重建普通Cell写入材料，也有失败回滚。参数变化、滑动、取消和离开页面继续由原会话管理；不要提前释放已失败清理的显示对象。
