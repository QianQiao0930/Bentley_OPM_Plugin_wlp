# 三个调节柄重叠：原因与修正

用户截图确认原生 GEARBOX_OPERATOR 显示三个柄，当前 CEL 件只看到安装根点附近一个。当前用户 place 日志的主插件 MVID 为 `5d1af1f8-140e-4148-8099-16db4f7801fe`，类为 SSP_CEL_VALVE_ACTUATOR，所选单元已变为“电动-执行器-DN800”、资源 SHA256 为 `D04BDAE90A3E565696F69863BEA880E551A0D61475BC75DC9455272960C6B866`。本轮不修改用户原 CEL。

本机 `Mdlapps/opmodeler.dll` 的 `TopworkDragManipulator.ExtractComponentPoints` 在 IL 0055/005A 使用实际类名与 GEARBOX_OPERATOR 做宽字符串相等比较，没有在此处查询继承链。原生类读取 TOTAL_HEIGHT / HANDLE_LENGTH / HANDLE_OFFSET；派生测试类进入通用分支，读取 LENGTH 和 DIAMETER。按局部原点 O 和安装矩阵 T，三个控制点为 O、O+T(0,0,LENGTH)、O+T(DIAMETER/2,0,LENGTH)。随后 PopulateDragHandleInfos 三次调用 AddControlPoint。

V6 的初始化将 LENGTH=1、DIAMETER=1。工作集 Units 为 MILLIMETRE，因此三点局部为 (0,0,0)、(0,0,1)、(0.5,0,1) mm，在几百毫米的模型范围下挤在同一图标附近。此前沿几何内方向标记查找是一个线索，直接原因已定位为这里的实际类名分支与占位尺寸；不能声称仅补两个点串就能修复。

_OnDrag 中 index0 调用 SlideComponentToPoint，index1/index2 调用 OrientComponentAxisToAxisAboutAxis。本次保留该官方调节器，不另造可见图标、不改原生 DLL 或全局类处理器。原生 IL 证据、原版本相关源码/DLL及用户日志位于本目录。

V6.1 在开始放置前，对冻结快照使用已有 true-scale 离线工厂读局部范围，统一换成 mm。控制高度取 Z 相对原点的最大绝对范围与 XY 径向范围一半的较大者；控制半径取 XY 径向范围与控制高度一半的较大者，避免扁平或细长单元重叠。通过 BMECObject.SetDoubleValueFromMM 设置 LENGTH=控制高度、DIAMETER=2×控制半径并回读核对；失败不进入官方放置。CEL几何不缩放、不平移、不重新居中，安装原点保持。距离是调节柄布局适配值，不作为厂家尺寸。

授权/无授权主工程独立输出0警告0错误，46项快照/EC协议/布局/真实XAML离线检查通过（8项新增范围、单位与退化几何检查），未运行 OPM。源 Schema 与已加载 DLL 未修改。

## 用户测试

1. 正常退出 OPM，备份并用本包 DLL/PDB 更新主插件；无需更新 V6 已装的 Schema。旧 ValveActuatorCallbackCheck.dll 保持。
2. 重开同一工作集，运行 STEELPROBE ACTUATOR，选 CEL 并在另一只没有执行机构的阀门上新放一件。旧 V6 件仍保存 1mm 参数，本版不自动改写旧件。
3. 预期新件出现三个分开的官方调节柄，分别试位置滑移和两种方向旋转，CEL整体响应且安装关联保留。柄位置依据整体CEL范围安排，不保证与用户模型中各个实体的几何中心逐一重合。
4. 结束官方工具后分别选执行机构/阀门运行 STEELPROBE ACTUATORCHECK；日志应有 Build=V6.1、NativeControlBranch=generic actual class name、LENGTH_mm/DIAMETER_mm 为与模型量级相当的正数，且正反向关联各为1。
5. 再检查Undo/Redo、随动、保存重开，核对外形/哈希、安装点与两个距离保留。若仍只见一个，反馈 place/inspect 日志及三个柄的拖动情况；编译和离线检查不算宿主已通过。
