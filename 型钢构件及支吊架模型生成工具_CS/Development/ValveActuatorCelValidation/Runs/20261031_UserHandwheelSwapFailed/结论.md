## 精确失败点

```text
AfterSetNonParametricElement.IsParametric=True
SwapError=宿主未切换到自定义几何模式
RollbackVerified=true
```

第一版从 API 工厂取得的仍是参数化手轮。`SetNonParametricElement` 没有令这个对象的 `IsParametric` 变为 False。代码在该保护条件处停止，**没有调用后面的 `BMECObjectWriter.Serialize`，没有执行源 CEL 删除，没有调用 Create**。

因此，本轮否定了“对既有参数化对象设置几何即可自动切换模式”的假设；没有检验 Geometry 的序列化/默认重读、移动、重生成或重开。不能扩大为“手轮关联失败”“CEL 导入失败”或“所有自定义执行机构路线都不可行”。

日志记录的回滚检查确认源 CEL、原手轮 Geometry/范围/父关联及父阀门范围恢复。这里是本次代码重读检查结论，未据此宣称任何后续稳定性场景通过。

## 第二版候选路线

本机公开 SDK 构造函数有 `BMECObject(IECInstance instance, bool nonParametric)`。V2 改为对现有手轮实例显式构造 `new BMECObject(wheel, true)`，明确记录构造后模式，再尝试序列化同一实例；不再指望 setter 切换已有 API 缓存对象。不调用 Create，不新增父关系，不修改全局 Schema。

V2 除保留原有回滚和范围检查外，还要求**默认方式重读**和存在的文档缓存都认定为非参数化；否则回滚，不以“显式包装器能画出来”作为成功。原生持久化模式若不接受该路线，再研究独立测试类的 Create3DElements 回调。V2 仅编译，尚未运行宿主。
