## 实现与部署

新增 `SSP_A1_NATIVE_TEST`，继承 `SUPPORT_LOCATION`。Modeling 中使用原生 `Support` handler / `PipeSupportPlacementTool`，组件实现为当前 DLL 的公开类 `SteelSectionProbe.A1NativeParametricComponent`。与旧试验不同，新件作为参数化组件创建，OPM 请求几何时调用原 A1 Calculator/Builder，保留真实螺杆和螺母，并同步当前组件原点到 SUPPORT_POINT_X/Y/Z。没有新增自动补偿移动监听。

BMECObject构造函数在Writer绑定RelatedInstance之前就调用组件Setup；因此Setup只能读取并验证自身DN/开口参数。父管/端口数据的SetPipeDiameter和A1支架长度设置移至几何阶段PrepareGraphics，仍在真正生成前严格执行。不能在构造期把尚未绑定父管当成错误，也不能因此跳过几何阶段的原生初始化。

局部几何沿 +X 管轴建模，原生变换负责世界位置和姿态。离线 Element 通过 SDK 的临时 BMECObject/LegacyGraphics 桥接成独立克隆的 ElementHolder；临时对象不 Create/Serialize，不建立模型或业务关系。句柄释放、OPM 实际扫掠、重生成和原生事务仍需宿主验证。

工作集需使用 [Install-A1NativeEditingTrial.ps1](../Deployment/Install-A1NativeEditingTrial.ps1)。默认只读预览，Apply 前关闭 OPM，实际写入要求备份目录。仅给基础、Modeling 和 Isoextractor 三份 schema 各增加同名试验类；不改已有类。ISO 标签在试验类限定读取 ALIAS，继承通用 SUPP 提取和支撑点规则。

```powershell
.\Deployment\Install-A1NativeEditingTrial.ps1 -SchemaDirectory '<工作集Standards/OpenPlant/Schemas完整路径>'
.\Deployment\Install-A1NativeEditingTrial.ps1 -SchemaDirectory '<同上>' -BackupDirectory '<备份完整路径>' -Apply
```

脚本提前验证全部文件，实际写前字节备份/SHA256，临时文件解析后替换；部分替换失败时回滚本次已替换文件。遇到同名项目自定义类拒绝覆盖，重复运行幂等。回退时在 OPM 关闭状态下按收据恢复三份备份；试验模型含新类时先保留对应 DLL/schema，避免失去编辑能力。

## 试放步骤

使用安装了试验 schema 的工作集，重启 OPM 加载本次 DLL。仅接受活动三维模型中可写、无保温、外径匹配 A1 目录的水平原生 PIPE。建议在试验 DGN 中分别放置“编辑测试”和“随动测试”两件，避免把手动改站位与原站位跟随混在一起。

1. 只选中一根水平裸直管，执行 `STEELPROBE A1TEST NATIVE`，默认放在中点。也可执行 `STEELPROBE A1TEST NATIVE 300 0` 指定距起点 300 mm、初始开口 0°。
2. 用 OPM 元素选择选中试验 A1，核对是否出现与自带支架相同的移动、旋转操作柄。记录操作柄缺失、显示或激活情况；初次生成成功不代表操作柄可用。
3. 用移动操作柄沿管轴移动，再用旋转操作柄绕管轴转动。每次操作后重新选中该 A1，执行 `STEELPROBE A1TEST CHECKEDIT`。该命令只读检查父管身份、当前定位点位于管轴段、组件 +X 对齐管轴、ISO 点与当前位置一致，以及试验类/参数/Design/SHOP；目视核对螺杆、螺母完整，不能变成默认挡板或 U 形简体。
4. 另外新放一件，不手动改变它的站位。只选择父管，用原生移动命令平移，然后选 A1 执行 `STEELPROBE A1TEST CHECK`；再单独测试父管水平旋转。CHECK 固定使用创建时站位，因此能够检测“管动夹不动”。组件绕管轴的滚转姿态仍需目视核对。
5. 分别做 Undo/Redo、保存关闭重开，再检查操作柄、外形、关系和位置。新建应单次 Undo 删除整件；原生编辑是否与几何/ISO点同次撤销属于宿主验收内容。
6. 移动后重新提取 ISO，核对符号位置、ALIAS 管架编号和 Supports 材料行。CHECK 的数据通过不能代替实际提取。

`CHECKEDIT` 通过只说明当前轴上定位与 ISO 数据一致，不能证明原站位随动通过。手动沿轴移动后，原 `CHECK` 仍会相对初始站位报告差异，这是两种检查的有意区别。两种检查都不自动修复模型。
