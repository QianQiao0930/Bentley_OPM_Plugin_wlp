### 必须提前说清的一点

"一键关闭**所有参考**里某个图层、主文件不动、作用于所有打开的视图、未匹配的参考要报告" ——
**这四条 key-in 一条都做不到**。key-in 的 `file:all` 按官方定义是 *"the master-file and all reference
attachments"*，会把主文件同名图层一起关掉，而且没有"未匹配报告"。

所以 key-in 在本需求里的定位是**探针**，不是最终形态。它要回答的只有 4 个问题（见 §3 判据表），
这些答案直接决定插件的写法。

## 1. 前置准备

1. 另存一份测试用主文件（或复制整个测试目录），**不要拿正式模型试**。
2. 主文件至少挂 2 个直接参考，其中 1 个参考**再挂 1 个嵌套参考**，且三者里都有你要关的那个图层同名层。
3. 打开 References 对话框，把每个参考的**文件名 / 逻辑名**抄下来（key-in 的 file-spec 要用）。
4. 记下图层名（含空格要加引号），例如 `"设备基础"`。

## 2. 测试步骤（在 OPM 的 Key-in 框逐条执行）

### T1 · 只读：确认图层名在各文件里的存在情况

```text
level usage file:all "设备基础"
```

- **只读，不改模型**，结果回报到 Message Center。
- **记录**：主文件和各个参考分别报了什么？嵌套参考出现在列表里了吗？

### T2 · 关键：能否"只关参考、不动主文件"

`file-spec` 支持文件名/逻辑名/表达式，所以先试表达式或逐个点名，而不是 `all`：

```text
level set display off file:*.dgn "设备基础"
```

如果表达式把主文件也扫进来了，改成逐个点名（空格分隔）：

```text
level set display off file:参考A.dgn file:参考B.dgn "设备基础"
```

- **记录**：主文件里的同名图层有没有被一起关掉？→ 这决定插件是否必须自己遍历附件。

### T3 · 嵌套参考是否可达

```text
level set display off file:参考A.dgn->嵌套C.dgn "设备基础"
```

- **记录**：嵌套件真的关掉了吗？`file:all` 在 T1 里有没有已经覆盖嵌套件？

### T4 · 恢复

```text
level set display on file:参考A.dgn->嵌套C.dgn "设备基础"
```

- 或统一用 `toggle`。确认能改回来，不要留下脏状态。

### T5 · 撤销

按 `Ctrl+Z`。

- **记录**：key-in 引起的图层显示变化能否一次撤销？（`ViewGroup.SynchViewDisplay` 有 `undoable` 参数，
  对话框操作通常可撤销，但 key-in 路径要实测。）

### T6 · 持久化（最关键的一条）

保存主文件 → 关闭 OPM → 重新打开主文件。

- **记录**：关掉的图层还是关的吗？**没保存就关文件**时又是怎样？
  （官方 REFERENCE FILECHANGED 文档说明图层显示设置写在主文件里并与附件关联，必须实测确认。）

## 3. 判据表：T1~T6 的结果决定后续怎么走

| 观察结果 | 结论与后续 |
| --- | --- |
| T2 能精确只关参考、T3 嵌套可达、T6 能持久化 | key-in 够用。把命令绑成功能键/工具栏按钮即完成"一键"，**不需要插件** |
| T2 无法只关参考（大概率） | 必须做插件：key-in 的 file-spec 没有"仅参考"语义 |
| T3 `->` 路径必须写全才能到嵌套件 | 插件必须自己递归遍历（`GetDgnAttachments()` 逐层） |
| T6 改完不保存就丢 | 插件需要在执行后调用 `DgnAttachment.Rewrite(writeSettings, writeLevelDisplaySettings)` |
| T1 有参考找不到该图层名 | 证实"按名称匹配 + 未匹配报告"是刚需（跨专业命名不一致） |

## 4. 若转插件：已经定好的技术骨架

命令行入口建议 `PYREFLEVEL`，目录按仓库惯例：

```text
关闭参考图层/
    关闭参考图层.py            入口：bentley_ui 面板 + RegisterKeyins() + PyMain()
    模块/参考图层/
        参考树.py              纯逻辑：枚举附件（含嵌套）、结果汇总
        图层开关.py            纯逻辑：图层名解析、显示位读写、SynchViewDisplay
```

核心调用（签名已在 `MSPyDgnPlatform.pyi` 核对）：

```python
from MSPyMstnPlatform import ISessionMgr
from MSPyDgnPlatform import ViewGroup, BentleyStatus

root     = ISessionMgr.ActiveDgnModelRef          # 官方示例同款入口
dgn_file = root.GetDgnFile()
status, vg = ViewGroup.FindActiveViewGroup(dgn_file)   # 返回元组 (ViewGroupStatus, ViewGroup)

def walk(ref, depth=0):
    """从 root 的附件开始 → 天然不含主文件；attachment 继承 DgnModelRef，可递归。"""
    for att in ref.GetDgnAttachments():            # DgnAttachmentArray 可直接 for（官方示例）
        yield att, depth
        yield from walk(att, depth + 1)

for att, depth in walk(root):
    lh = att.GetLevelCache().GetLevelByName('设备基础')   # 每个参考有自己的图层表！
    # 判有效 → 取 lh.GetLevelId()
    for view_number in range(8):                   # 视图号 0 起（存根：0..MAX_VIEWS-1，待实测）
        vi = vg.GetViewInfo(view_number)
        vi.SetLevelDisplay(att, level_id, False)
        vg.SynchViewDisplay(view_number, True, True, False)  # levelsChanged, undoable, synchViewTitle
```

要写进实现的坑（详见对话记录）：

1. **图层表是按文件各自的** —— 绝不能用主文件的 `LevelId` 去关参考的层，必须用该附件的 `LevelCache` 解析。
2. **显示位是 per-view 的** —— 只关一个视图没用，要遍历打开的视图。
3. **嵌套参考可能不吃自己的 mask** —— `REF_NESTOVERRIDES_NEVER`（见 `EnsureLevelMaskCoverage` 存根注释）、
   `DoNotDisplayAsNested`、`IsDisplayed()` 为假时要能解释"关了还看得见"。
4. **`SynchViewDisplay` 的 `undoable=True`** 让一次 `Ctrl+Z` 撤销整批，这是"可回退"的正解。
5. **通配匹配**用 `LevelCache.GetHandles()` 遍历 + 自己写通配（`GetLevelByName` 只精确匹配）。
6. 参考件若缺 logical name，file-spec / 报告里用 `GetAttachFileName()`。
