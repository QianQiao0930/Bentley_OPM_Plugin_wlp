# OpenPlant Modeler 管道标高对齐插件开发规范

## 1. 文档目的

本文档定义 Pipe Elevation Align 插件的功能和开发方法。

插件用于 OpenPlant Modeler。

插件对多个管道执行标高对齐。

插件支持以下对齐方式：

- 管底对齐。
- 管中心对齐。
- 管顶对齐。

插件必须保持 OpenPlant 数据和图形的一致性。

插件不得只修改图形，而不检查 OpenPlant 对象数据。

---

# 2. 设计原则

## 2.1 使用 OpenPlant 对象作为主要对象

程序必须先识别 OpenPlant 对象。

程序不得只根据 DGN Element 类型识别管道。

程序必须确认对象属于 `PIPE` 类或其有效派生类。

程序应通过 OpenPlant SDK 获取和修改管道对象。

如果目标版本不提供所需接口，程序才可以使用 DGN 图形变换。

程序使用 DGN 图形变换时，必须执行数据一致性检查。

---

## 2.2 不依赖选择集顺序

程序不得把 Selection Set 的返回顺序作为业务顺序。

程序必须明确获取基准管。

推荐的交互顺序如下：

1. 启动命令。
2. 选择基准管。
3. 选择对齐方式。
4. 选择目标管。
5. 显示预览。
6. 执行修改。

基准管必须存储为独立对象。

目标管必须存储为集合。

程序不得通过全局 `Ordered<ElementId>` 推断基准管。

---

# 3. 功能范围

## 3.1 第一版本功能

第一版本只处理水平直管。

第一版本支持不同公称直径。

第一版本支持不同外径。

第一版本支持多个目标管。

第一版本支持以下基准：

| 模式 | 英文名称 | 对齐基准 |
|---|---|---|
| 管底 | BOTTOM | 管道外表面最低点 |
| 管中心 | CENTER | 管道中心线 |
| 管顶 | TOP | 管道外表面最高点 |

程序必须在执行前检查管道是否水平。

---

## 3.2 第一版本不处理的对象

第一版本不自动调整以下对象：

- 斜管。
- 弯头。
- 三通。
- 异径管。
- 阀门。
- 法兰。
- 支吊架。
- 仪表。
- 设备管口。

程序发现这些情况时，必须停止危险操作。

程序必须给出明确的信息。

---

# 4. 后续版本功能

后续版本可以增加 Run Align 模式。

Run Align 模式移动一组连接对象。

该模式必须检查连接边界。

后续版本可以增加 Pipe Route Adjust 模式。

该模式自动修改竖向管段和弯头。

该功能必须使用 OpenPlant 路由逻辑。

程序不得通过简单图形平移模拟重新布管。

# 5. 术语

本文档使用以下固定术语。

**Reference Pipe**

基准管。

插件从该管道取得目标标高。

**Target Pipe**

目标管。

插件移动该管道。

**Center Elevation**

管道中心线标高。

**Bottom Elevation**

管道最低外表面标高。

**Top Elevation**

管道最高外表面标高。

**Effective Diameter**

用于计算顶部和底部标高的有效直径。

**Move Group**

允许一起平移的一组 OpenPlant 对象。

后续内容必须使用这些术语。

不要为同一对象使用不同名称。

# 7. PipeInfo 数据模型

程序不应在业务逻辑中反复读取 EC 属性。

程序应先把管道数据转换成统一对象。

推荐使用以下模型。

```csharp
public sealed class PipeInfo
{
    public ElementId ElementId { get; init; }

    public object OpenPlantObject { get; init; }

    public DPoint3d StartPoint { get; init; }

    public DPoint3d EndPoint { get; init; }

    public double OutsideDiameter { get; init; }

    public double InsulationThickness { get; init; }

    public bool IsHorizontal { get; init; }

    public bool IsReadOnly { get; init; }

    public bool HasConnection { get; init; }
}
```

`OpenPlantObject` 的实际类型应根据目标 SDK 修改。

业务层不得直接依赖多个 OpenPlant 版本的具体类。

# 8. 标高计算方法

## 8.1 不推荐的方法

正式版本不应使用下面的方法作为主要算法：

```csharp
Range3d range = element.GetRange();

bottom = range.Low.Z;
top = range.High.Z;
center = (range.Low.Z + range.High.Z) / 2.0;
```

该方法可以用于 POC。

该方法不适合作为长期接口。

Element Range 是图形包围范围。

它不是管道工程定义中的中心线数据。

自定义表示方式也可能改变 Range。

---

# 9. 推荐标高算法

程序必须先取得管道中心线。

设中心线标高为：

```text
Zc
```

设管道外径为：

```text
Do
```

对于裸管：

```text
Bottom = Zc - Do / 2
Center = Zc
Top    = Zc + Do / 2
```

对于目标管，位移为：

```text
ΔZ = ReferenceElevation - TargetElevation
```

程序只修改 Z 坐标。

程序不得修改 X 和 Y 坐标。

---

# 10. 保温层处理

插件应提供表面对齐选项。

推荐设置两个模式：

```text
Pipe Outside Surface
Insulation Outside Surface
```

对于裸管表面：

```text
Deffective = Do
```

对于保温外表面：

```text
Deffective = Do + 2 × Tinsulation
```

然后使用：

```text
Bottom = Zc - Deffective / 2

Top = Zc + Deffective / 2
```

程序必须明确显示当前表面模式。

程序不得自动猜测用户需要哪一种表面。

---

# 11. 水平管判断

程序必须检查中心线方向。

假设管道端点为：

```text
P1 = (X1, Y1, Z1)
P2 = (X2, Y2, Z2)
```

计算：

```text
ΔZ = Z2 - Z1
```

如果：

```text
abs(ΔZ) <= HorizontalTolerance
```

则程序可以把管道作为水平管处理。

推荐把容差写入配置。

不要把容差写死在业务代码中。

示例：

```text
HorizontalTolerance = 1 mm
```

项目可以修改该值。

---

# 16. 对齐计算

推荐建立统一函数。

```csharp
double GetAlignmentElevation(
    PipeInfo pipe,
    AlignmentMode mode,
    SurfaceMode surfaceMode)
{
    double diameter = pipe.OutsideDiameter;

    if (surfaceMode == SurfaceMode.Insulation)
    {
        diameter += 2.0 * pipe.InsulationThickness;
    }

    double z = pipe.StartPoint.Z;

    switch (mode)
    {
        case AlignmentMode.Bottom:
            return z - diameter / 2.0;

        case AlignmentMode.Top:
            return z + diameter / 2.0;

        default:
            return z;
    }
}
```

实际代码必须统一单位。

业务层建议使用一个内部长度单位。

---

# 17. 单位系统

不要在各函数中重复执行 UOR 换算。

建立独立 Unit Service。

例如：

```csharp
public interface IUnitService
{
    double UorToMillimeter(double value);
    double MillimeterToUor(double value);
}
```

业务计算建议统一使用毫米。

这样可以降低单位错误风险。

OpenPlant 属性的单位必须单独检查。

程序不得假设所有 EC 长度属性都是毫米。

---

# 18. OpenPlant 对象修改策略

这是本插件最重要的设计要求。

程序必须优先使用 OpenPlant SDK 修改智能对象。

推荐优先级如下。

## Level 1

使用 OpenPlant SDK 的业务对象接口修改位置。

这是推荐方法。

## Level 2

使用 OpenPlant SDK 修改对象变换信息。

程序随后执行 OpenPlant 更新。

## Level 3

使用 DGN Element Transform。

只有验证 OpenPlant 数据同步后，才能使用该方法。

# 19. 禁止的正式实现

正式版本不得只执行：

```csharp
element.ApplyTransform(transformInfo);
element.ReplaceInModel(element);
```

然后结束命令。

该方法只修改 DGN 图形时风险较高。

程序必须继续检查以下数据：

```text
OpenPlant object location
EC data
connection data
component transformation
pipeline relationship
isometric data
```

# 20. OpenPlantVersionAdapter

OpenPlant 不同版本可能提供不同 API。

程序应增加版本适配层。

例如：

```csharp
public interface IOpenPlantPipeAdapter
{
    bool IsPipe(Element element);

    PipeInfo GetPipeInfo(Element element);

    bool CanMove(PipeInfo pipe);

    void MovePipe(
        PipeInfo pipe,
        double deltaZ);

    IEnumerable<object> GetConnectedComponents(
        PipeInfo pipe);

    bool ValidateConnections(
        PipeInfo pipe);
}
```

业务代码只调用该接口。

版本相关代码放在实现类中。

例如：

```text
OpenPlant2024Adapter
OpenPlantConnectAdapter
```

这样可以减少版本升级成本。


# 22. 默认安全模式

第一版本建议采用 Safe Mode。

Safe Mode 只移动可以安全平移的对象。

如果目标管连接到未移动对象，程序停止该目标管。

程序显示原因。

示例：

```text
Pipe 12345 has a fixed connection.
The command did not move this pipe.
```

这样可以避免产生隐藏断口。

---

# 23. Move Group 模式

后续版本可以增加 Move Group。

程序从目标管开始检查连接对象。

程序把允许一起移动的对象加入 Move Group。

整个 Move Group 使用相同的 `ΔZ`。

这类对象可以包括：

```text
Pipe
Elbow
Flange
Valve
Reducer
Tee
Support
```

是否可以移动某类对象必须由规则控制。

---

# 24. 边界连接

Move Group 必须定义 Boundary Connection。

例如：

```text
Equipment nozzle
Pipe outside selected run
Fixed support
Branch outside move group
Reference model component
Locked component
```

程序发现 Boundary Connection 时，必须确定移动是否会产生断开。

如果会产生断开，程序停止操作。

# 27. Apply 操作

用户选择 Apply 后，程序执行完整检查。

程序执行以下步骤：

1. 再次读取所有 Pipe 对象。
2. 检查 Element 是否仍然有效。
3. 检查 Reference Pipe。
4. 检查 Target Pipe。
5. 检查水平状态。
6. 检查锁定状态。
7. 检查只读状态。
8. 检查连接状态。
9. 计算每根管道的 `ΔZ`。
10. 执行 OpenPlant 移动。
11. 更新模型。
12. 检查连接。
13. 报告结果。

如果关键检查失败，程序不得执行部分危险修改。

---

# 28. Undo

一次 Apply 必须形成一个用户操作。

用户执行一次 Undo 时，应撤销整个 Align 操作。

程序不得要求用户连续执行多个 Undo。

具体 Transaction API 必须根据目标 OpenPlant SDK 确定。

# 34. 主要计算示例

基准管参数：

```text
Center elevation = 5000 mm
Outside diameter = 219 mm
```

选择 Bottom 模式。

则：

```text
Reference bottom
= 5000 - 219 / 2
= 4890.5 mm
```

目标管参数：

```text
Center elevation = 5200 mm
Outside diameter = 108 mm
```

目标管底标高为：

```text
Target bottom
= 5200 - 108 / 2
= 5146 mm
```

移动量为：

```text
Delta Z
= 4890.5 - 5146
= -255.5 mm
```

程序将目标管向下移动 255.5 mm。

---

# 35. 为什么不能使用中心标高差完成管底对齐

不同外径的管道不能只比较中心标高。

例如：

```text
DN200 pipe
DN100 pipe
```

如果两根管道中心标高相同，它们的管底标高通常不同。

因此 Bottom 模式必须使用外径。

Top 模式也必须使用外径。

---

# 36. GetRange 的用途

`GetRange()` 可以保留。

它适合执行以下操作：

```text
Debug check
Preview check
Geometry sanity check
```

它不应成为工程标高的唯一数据源。

中心线和外径应作为主要数据源。

# 37. 性能要求

程序应一次读取目标对象数据。

程序不得在循环中重复执行完整 EC 搜索。

程序应缓存 `PipeInfo`。

程序应批量执行 Validation。

程序应避免频繁刷新视图。

完成移动后再统一刷新模型。

# 39. 验收标准

正式版本必须满足以下条件。

程序能明确选择 Reference Pipe。

程序不依赖 Selection Set 顺序。

程序支持 Bottom、Center 和 Top。

程序正确处理不同外径。

程序正确处理单位。

程序拒绝不支持的斜管。

程序不会静默破坏管道连接。

程序执行后，OpenPlant 属性保持正确。

程序执行后，Connectivity Check 不产生新的错误。

程序执行后，模型重新打开仍然正常。

程序执行后，轴测图功能保持正常。

一次 Undo 可以撤销整个操作。

# 42. 对原始方案的结论

原始方案适合作为概念验证。

以下设计可以保留：

```text
Reference elevation
Target elevation
Delta Z
Bottom / Center / Top modes
Element ID cache
Debug EC dump
```

以下设计建议修改：

```text
Selection event order
    ↓
Explicit reference selection

Element.GetRange()
    ↓
Centerline + outside diameter

Direct Element transform
    ↓
OpenPlant object move

Move pipe only
    ↓
Topology validation

Global static selection state
    ↓
Tool state object

Scattered unit conversion
    ↓
Unit service

Version-dependent API in business code
    ↓
OpenPlant version adapter
```

最终架构应把“标高计算”和“OpenPlant 对象修改”完全分开。

这样可以保护业务算法。

这样也可以降低 OPM 版本升级的成本。
