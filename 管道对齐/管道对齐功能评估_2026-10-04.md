# 管道对齐功能评估与修复记录

评估日期：2026-10-04。对象：`PipeAlign_CS` 当前工作区源码、《管道对齐插件开发指南》以及本机 `%LOCALAPPDATA%\PipeAlign\PipeAlign_debug_log.txt`。本轮未启动或操作 OpenPlant Modeler，未修改 DGN，也未替换外部部署目录的 DLL。

## 结论

现场追加（08:52 日志）：带弯头管道被跳过的直接原因是「读取端口失败：集合已修改；可能无法执行枚举操作」。本轮增加的 GetConnectedComponentAtPort 查询会刷新正在遍历的 SDK Ports 集合；已改为复制 Ports 和 ConnectedComponents 后遍历。另已阻止普通 DgnElementSchema 实例参与 OpenPlant 探测，消除其无 LENGTH 属性造成的误导警告。追加 DLL 已编译，未在宿主复测；使用者截图选择的是 SINGLE，整组移动仍须明确改为 GROUP。

**修复前没有完整实现指南。** 基础对齐公式、显式基准选择、参数、窗口、点取和单位标定已存在，但 Move Group 的后续计划与执行链有实质缺陷，预览违反“不修改模型”，失败恢复和成功判断也不满足正式版本要求。

本轮修正了可由代码与现场日志确认的问题，生成了新版 Release DLL。**代码修复与离线测试通过，不代表新版已在真实 OpenPlant 模型中验收通过。** §38 的 T17～T20、真实英制项目和连通组移动仍需宿主实测。

## “报错或跳过”的现场证据

| 日志时间 | 证据 | 判断 |
| --- | --- | --- |
| 00:01:12 | L1/L2/L2b 都报“按实例 ID 取不到 OpenPlant 实例” | 失败发生在查找对象阶段；原摘要却说“修改接口已调用、已回退”，诊断失真。已增加 SDK 查询失败时的 API 对象缓存解析路径 |
| 00:01:37 | 独立 DN80 管道由 Z=0 移到 79.4 mm，几何与 EC 均更新 | 历史版本并非完全不能移动，但只证明这一根管道、这一轮成功 |
| 00:12:54～00:13:36 | 同一根管读到 `FLUID_PORT` 两条和弯头两条，合并为四条连接 | `Port.ConnectedTo` 指向对端端口，`ConnectedComponents` 指向构件；直接按两种 ID 去重不能合并 |
| 00:13:36 | 整组因“边界对象 FLUID_PORT”拒绝 | 明确 bug：端口被当成未知边界构件。已按端口解析其所属对端构件，再按构件实例 ID 合并 |

默认「只移动选中的管道」在遇到未一起移动的相连对象时跳过，是 §22 的安全要求。不能通过关闭拓扑检查或把 `FLUID_PORT` 加入可移动类别解决整组问题。

## 验证范围及复测步骤

Release 主工程与连接 API 探针：0 错误、0 警告。离线回归：38/38 通过。历史默认 ApiProbe 包含不可消费的原生接口，仍不能整体编译；本轮使用 `/p:ConnectivityOnly=true` 独立验证两个连接接口。原有其它插件的工作区修改未触碰。

新 DLL：`PipeAlign_CS/bin/Release/net48/PipeAlign.dll`。关闭 OPM 后，按 README 部署步骤复制新版，再启动加载。建议在测试 DGN 副本中按下列顺序验收：

1. 孤立水平直管：Bottom / Center / Top，各做向上和向下移动，并核对不同外径、保温和已对齐不动。
2. 连通管线：选择「连同连通对象一起移动」，只选一根水平管作为起点。预览成员应包含相连弯头、其它管段，所有成员的 ΔZ 完全一致，不能再出现 `FLUID_PORT` 边界误判。
3. 边界保护：组内连接设备管口、固定支吊架、参考或锁定成员时，整组不修改；多个种子要求不同位移时明确拒绝。
4. 预览：只预览后取消/关闭，不应新增 DGN 元素；预览前后的保存状态与 Undo 不应被预览污染。
5. 一次 Undo 撤销全部成员；受控制造中途失败时整批回到基线，不残留半组移动。
6. 保存并重开模型，核对标高、EC、连接和管线关系；运行官方 Connectivity Check 与 Isometric，要求无新增错误。
7. 在真实英制项目重复坐标、外径、预览、移动与保存重开验证。

### 仍需重点关注的限制

- 目前连接复核比较对端构件 ID 集合，不能替代端口几何、Joint、管线归属和 ISO 的完整一致性验收。
- 适配器仍逐成员执行 DiscoverConnectionsEx / UpdateConnections；实际组移动中是否在中间状态重建或丢失关系，需要真实模型确认。新增最终复核会拒绝并尝试整批回退，但不能据此宣称 SDK 关系写回链已验收。
- 管件和竖管跟随移动依赖该成员真实几何、API 坐标探测与 EC 可读性；探测未通过仍会拒绝，不能为“看起来能动”绕过单位证明。
- DGN 事务位置回退能否覆盖所有 OpenPlant API/关系写入，以及 EndUndoGroup / SaveAndCleanUpUndo 的运行效果，只能在宿主验证。
- 本轮未验证显示容器生命周期、窗口关闭清理、英制预览或真实组移动。新版 DLL 已生成，尚未部署和实测。
